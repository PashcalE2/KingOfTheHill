# Царь горы

Это аддон который идейно копирует одноименный режим в шутерах.

## Идеи организации аддона

Первоначально, я решил разделить обязанности между кусками програм с помощью создания различных SENT (ScriptedENTity). Этот метод показался мне более удобным чем разделение по lua-модулям (`module(...), require(...)`) в плане запуска на своей локалке (не требуется перезапуск сервера для обновления аддона).

Недавно заметил относительно классную штуку:
```lua
-- game_manager/init.lua
-- глобальная переменная видна в прочих файлах проекта
KOTFPlayers = {}
```

Кажется, она очень плоха тем, что эта переменная становится доступна для других аддонов (например LuaPad). Я не против пользоваться такой фичей, поэтому когда кто-то будет это смотреть - обратите вниманеия на такие "глобальные" переменные и не удивляйтесь, почему я могу их использовать в прочих файлах.

### Логика игры в целом

Содержится в [game_manager](lua/entities/game_manager/). 

Ентити такого класса должна быть ЕДИНСТВЕННОЙ на сервере, так как с её помощью идет манипуляция над переменными аддона, а так же другими ентитями аддона.

### Логика ключевой точки

Содержится в [critical_point](lua/entities/critical_point/). 

### Логика отсчета до победы

Содержится в [win_score_counter](lua/entities/win_score_counter/). 

## Правила

Читаем код и не жалуемся (позже распишу).

## Этапы

Набор шагов для "успешного" запуска этой дичи.

### Подготовка

0. Удалите вызов `createRandomTestCase()` в [game_manager/init.lua](lua/entities/game_manager/init.lua) (иначе все игроки будут участвовать).
1. Ставим `game_manager` ОДИН РАЗ (если поставили случайно второй - удаляйте оба, возможно пофикшу).
    - После удачного спавна одной ентити -- появится хук на чат.
2. Ставим `critical_point` -- можно несколько штук.
3. Взаимодействие с чатом.

В чат можно писать кучу команд, сейчас не вспомню все, но вот несколько:
1. `/join <teamName>` -- записать себя в команду (указывать команду не обязательно, тогда игрок запишется в рандомы).
2. `/start_game` -- запустит жизненно важные процессы для точек и менеджера игры.
3. ...

### Условие победы

Короче при запуске игры сервер ентити `win_score_counter` для каждой команды.
В них хранится отсчет до победы. Каждую секунду, за каждую захваченную ключевую точку - отнимается одно очко.

Изначальное количество очков регулируется в [win_score_counter/shared.lua](lua/entities/win_score_counter/shared.lua)


### Игра

1. Подходим к точкам.
2. Происходит захват / борьба / отхват / защита / восстановление (правила распишу позже).
3. Как только точка захвачена (не важно, отхватывают её или нет) -- она идет в счет победы.
4. У кого счет упадет до 0 раньше остальных - тот победил (а что если у нескольких команд одновременно упадёт? пока что "побеждают" все).
